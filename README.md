# syncGaroonToGoogle

Garoon の予定を Google Calendar に一方向で同期します。

## 実装の構成

| 実装 | フォルダー | 状態 | 利用手順 |
| --- | --- | --- | --- |
| Google Apps Script版 | [gas/](gas/) | 旧来の実装。フォルダー整理による同期ロジックの変更なし | [GAS版 README](gas/README.md) |
| Chrome拡張機能版 | [chrome-extension/](chrome-extension/) | 追加開発中の初期実装。元仕様との未解消差分あり | [Chrome拡張版 README](chrome-extension/README.md) |

GAS版のソースと設定は `gas/` に配置しています。GAS専用の認証、project作成、配備と依存関係準備のスクリプトは `gas/script/` にまとめています。

ルートの `script/postCreate.sh` は開発環境全体の起点です。GAS固有の準備処理は `gas/script/initNodejs.sh` へ委譲します。GAS専用処理をルートの `script/` に直接持たせない構成です。

Chrome拡張版のソース、設定画面とテストは `chrome-extension/` 内で管理します。GAS版へのアップロードには含めません。

## 移行の目的と変更範囲

Garoonで2要素認証が必要になったため、GAS版のパスワード認証から、Chrome内のログインセッションを利用する方式への移行を進めています。

今回合意している変更は次のとおりです。

| 項目 | 旧GAS版 | Chrome拡張版の方針 |
| --- | --- | --- |
| Garoonの認証 | ログイン名とパスワードによるAPI認証 | 同じChromeプロファイルでログイン済みのGaroonタブのセッションを利用 |
| Googleへのアクセス | GASに与えた実行権限を利用 | 拡張機能用OAuthクライアントと初回の同意でAPIを利用 |
| 同期の実行条件 | GASの時間主導トリガーと勤務時間帯判定 | Garoonタブを開いている間、5分ごとに実行 |
| 状態の確認 | GASの実行ログ | アイコンとポップアップで同期可、同期中と同期不可を表示 |

これ以外の同期仕様は、旧GAS版の振る舞いを維持することを基本方針とします。

## 同期先カレンダー名と共通仕様

同期先カレンダー名は、旧GAS版にもある `CalendarName` に相当する設定です。拡張機能化で新たに追加した同期条件ではありません。

- 振り分けタグがない予定は、デフォルトの同期先カレンダーへ登録します。
- `SyncTargetCalendars` に登録したタグがある予定は、対応する名前のカレンダーへ振り分けます。
- カレンダーが存在しない場合は作成します。
- `#nosync` は振り分けタグより優先して同期対象から除外します。

タイトル、説明欄、終日予定と繰り返し予定の変換仕様は[項目マッピング](docs/Garoon_GCal_項目マッピング.md)を参照してください。

## 現在のChrome拡張版に残っている仕様差分

以下は現実装を照合して確認した差分です。認証と実行条件の変更とは別に扱うべきものであり、変更後の仕様として合意したものではありません。今回のフォルダー整理とREADME更新では、これらの同期ロジックは修正していません。

| 項目 | 旧GAS版 | 現在のChrome拡張版 | 影響 |
| --- | --- | --- | --- |
| カレンダーの検索範囲 | 自分が所有する同名カレンダーを検索 | カレンダー一覧の同名候補を検索し、ownerまたはwriter権限を要求 | 共有カレンダーも同期先の候補になる |
| 同名カレンダーが複数ある場合 | 最初のカレンダーを使用 | エラーで停止 | 従来動いていた設定でも同期が止まる可能性がある |
| 開始時刻のみ、または開始と終了が同時刻の予定 | 開始と終了を同時刻に設定 | 1分の予定に補正 | Google側に表示する予定の長さが変わる |
| 更新判定 | Garoonの更新日時が保存タグより新しいかを秒単位で比較 | 日時タグの不一致に加え、タイトルや日時などの内容も比較 | Garoonに更新がなくてもGoogle側の編集を上書きする |
| 既存の同期済み予定 | 従来の同期タグで認識 | 同期元情報を追加し、旧タグだけの予定は引き継ぎ設定を有効にしたときだけ認識 | 引き継ぎを無効にして同じカレンダーを使うと新旧予定が重複する |
| 差分判定の対象カレンダー | デフォルトカレンダーの予定を取得して判定し、作成や更新時に他の同期先も検索 | 登録した全同期先カレンダーの予定を取得して一括判定 | 振り分け先の更新や削除の判定範囲が広がる |
| 同期期間と境界 | GASの実行環境で日付境界を計算し、終了を最終日の23:59:59に設定 | 設定したIANAタイムゾーンで計算し、翌日0時を終了境界として使用。期間をまたぐGoogle予定の削除を抑止 | 境界付近と長期間の予定で取得や削除の判定が異なる |
| 設定値の制限 | 日数は正の整数。振り分け先の件数に明示的な上限なし | 日数は0から366日。振り分け先は20件までで名前なども検証 | 元の設定値をそのまま使えない場合がある |
| カレンダー間の移動 | 移動元を削除してから移動先を作成 | 移動先を作成してから移動元を削除 | 失敗時の残り方と復旧処理が異なる |

Chrome拡張版には、全ページ取得に失敗したときの反映中止と、決定的なイベントIDによる二重作成防止も追加しています。これらのエラー処理と、上表の利用者から見える仕様差分は区別して評価する必要があります。

照合対象は[GAS版のカレンダー選択](gas/src/dataobject/GCal.js)、[GAS版の差分判定と日時変換](gas/src/service/ScheduleEventService/GaroonEventService.js)、[GAS版の同期処理](gas/src/service/SyncEventService.js)、[拡張版のカレンダー選択](chrome-extension/src/GoogleCalendarClient.js)と[拡張版の同期処理](chrome-extension/src/SyncService.js)です。

## 検証状況

GAS版のフォルダー改名時に、移動した25ファイルの内容が元と同一であることを確認しました。構文、設定と関連パスも検証しています。

GAS専用スクリプトの移動後は、認証と配備のコマンドをモックに置き換え、リポジトリ直下、`gas/` と `/tmp` から計15回実行し、GAS projectの場所を正しく解決することを確認しています。

Chrome拡張版にはNode.jsの自動テストと構文チェックがあります。実際のGaroonとGoogleアカウントによる接続確認は未実施です。テストの成功は、旧GAS版との互換性が確保されたことを意味しません。

## 注意点

- GAS版は `import` / `export` を使うモジュール構成に対応していません。Chrome拡張版ではES Modulesを使います。
- どちらもGoogle CalendarからGaroonへの逆方向同期は実装していません。
