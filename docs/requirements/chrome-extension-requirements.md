# Chrome拡張機能の要件

利用者と保守担当者が、同期の対象と制約を判断するための仕様です。操作は[利用手順](../procedures/chrome-extension-usage.md)を参照してください。

## 利用条件

- Chrome 120以降を利用する。
- 同じChromeプロファイルで、設定したユーザーのGaroonタブを開いておく。
- 休止中のタブは利用しない。
- Garoonへのログインと2要素認証はGaroonの画面で完了する。
- Google Calendarへのアクセスは拡張機能に対して許可する。

Chrome終了中とPCのスリープ中は同期できません。自動同期は指定した間隔を目安に実行し、時刻を厳密には保証しません。

## 同期先の振り分け

| 項目 | 動作 |
| --- | --- |
| タグとカレンダー名 | 別々に設定する。同じカレンダー名を複数行で指定できる |
| タグ | 英数字とアンダースコアを使う。大文字小文字を区別しない |
| 複数の一致するタグ | メモ内で最初に出現するものを採用する |
| タグが空欄の行 | 設定したタグに一致しない予定の同期先になる |
| 空欄の行がない場合 | 一致するタグがない予定を同期しない |
| `#nosync` | 他のタグより優先して同期対象から除外する |
| 設定行 | 最大21行。同じタグと空欄はそれぞれ1行まで |
| カレンダーの解決 | 名前で検索する。不足するものは同期時に作成する |
| 同名のカレンダーが複数ある場合 | 書き込みを中止する |

同じカレンダーを使う設定行が残っている限り、そのカレンダーは同期対象です。設定行がすべてなくなったカレンダーは以後検索しません。

## 予定の変換

| Garoonの情報 | Google Calendarへの反映 |
| --- | --- |
| `eventMenu`と`subject` | `【予定メニュー】件名`。メニューがない場合は件名だけ |
| 参加者名 | 説明欄の「参加者」へ転記する。招待先には登録しない |
| `notes` | 説明欄の「メモ」へ転記する |
| 時刻指定予定 | 開始と終了をUTCの日時に変換する |
| 終日予定 | 開始日と排他的な終了日を設定する |
| 開始時刻のみの予定 | 開始から1分間の予定として登録する |
| 繰り返し予定 | 各回を独立した予定として登録する |

公開範囲など、変換対象に含まれない項目は転記しません。カレンダーの共有範囲はGoogle側で管理します。

## 予定の照合

- 通常予定はGaroonの`id`で照合する。
- 繰り返し予定は`id-repeatId`で照合する。
- Google予定のprivateとsharedの拡張プロパティから`GAROON_UNIQUE_EVENT_ID`を読む。
- 同期元情報がある場合は、Garoonのオリジンとログイン名の一致も確認する。

同じカレンダー内で識別子が重複していたら、予定への書き込みを中止します。件名と日時だけで同一予定かを推測しません。

Garoonの更新日時と転記対象の項目を比較します。Google側で転記項目を編集した場合も、次の同期でGaroonの内容に合わせます。

## 期間と削除

同期期間は設定したタイムゾーンの日付で決めます。今日を含み、終了日は翌日の0時を排他的な境界とします。

通常の同期で削除するのは、この同期元の管理情報が記録された期間内の予定です。手動作成の予定と別の同期元が明記された予定は変更しません。期間境界をまたぐGoogle予定を、取得できなかったという理由だけで削除しません。

「予定を全削除」は通常の同期と対象が異なり、指定カレンダーの全期間を対象にします。手動作成の予定も含み、繰り返し予定はシリーズ単位で全回を削除します。カレンダー本体は残します。自動同期は操作開始時に停止し、取消後と削除完了後も停止したままです。

## 自動同期

設定画面でON/OFFと分単位の間隔を保存します。間隔は1分以上の整数です。初期値は`DEFAULT_SETTINGS`で管理します。

ポップアップからはON/OFFだけを変更します。再開時は保存された間隔を使います。OFFにすると自動同期のアラームを解除し、実行中の同期にも停止を要求します。進行中のAPIリクエストが完了するまで待ってから中断し、反映済みの変更は残ります。

Worker起動時には保存された設定からアラームを復元します。同じ間隔のアラームがある場合は作り直しません。同期中に次のアラームが発生しても重複実行せず、その回をスキップします。Chromeの実行遅延と再起動時の動作は[アラームの公式仕様](https://developer.chrome.com/docs/extensions/reference/api/alarms)を前提にします。

## 失敗とデータの扱い

全件取得と検証を終えてから予定の反映計画を作ります。認証エラーや不完全な取得結果を空の予定一覧として扱いません。不足するカレンダー自体の作成は、予定取得より先に行う場合があります。

同期は約4分を目安に打ち切ります。件数が多い場合は同期期間を短くします。取得するページ数には上限があり、上限到達は成功にしません。

GaroonのパスワードとCookieを読み取って保存する処理はありません。Googleの認証トークンと予定本文を永続化しません。

再開と結果表示のために、次の情報を保存します。

- 設定
- 同期状態と接続結果
- 全削除の確認用IDとETag
- 全削除の処理件数と実行結果

## 配布と更新

Windows向けに、開発ツールが不要な配布ZIPをGitHub Releasesへ公開します。利用手順は`README.md`として同梱し、マッピング図も含めます。Chromeには展開した`extension`フォルダーを読み込ませます。

リリース番号は`v1.2.3`形式のGitタグから設定します。タグpush後の自動検証に成功した配布物だけを公開します。実行ファイルと文書は同じタグの内容で揃えます。

利用者は`update.bat`から最新の正式リリースへ更新できます。更新前に取得内容を検証し、不要になった実行ファイルも削除します。バックアップは作成せず、置き換え中の失敗は再実行またはZIPの再展開で復旧します。同じ版でも不足ファイルは修復します。

導入先とChromeの保存領域を維持し、更新後は利用者が拡張機能を再読み込みします。利用者のトークンは配布物に含めません。導入と更新の条件は[利用手順](../procedures/chrome-extension-usage.md#リリース版を導入する)を参照してください。
