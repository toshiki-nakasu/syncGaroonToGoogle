# Chrome拡張機能を変更するときの注意

拡張機能を変更するAIが、ローカルの単純なモックでは見逃す条件を確認するための指示です。[共通方針](maintenance.md)を適用し、通常の設計は[クラス構成](../design/chrome-extension-design.md)を参照してください。

## 保存領域を通る比較を変更する場合

Chromeの保存領域では辞書のキー順が変わります。確認用データの内容比較にJSON文字列の一致を使うと、同じ予定でも変更されたと誤判定します。

IDとETagの値を比較し、キー順が変わるテストを維持してください。画面からWorkerを通すテストでも、保存領域の往復を再現します。

## Workerと排他を変更する場合

Workerのメモリー上の状態は永続化されません。全削除の進捗と自動同期の設定がメモリーだけに残る設計へ戻さないでください。

設定の更新順と実行の排他は役割が異なります。一つのロックに統合すると、実行中の停止を受け付けられない場合があります。停止要求と再開、全削除の登録が重なるテストを確認します。

## API呼び出しを変更する場合

Workerの`fetch`をクライアントのメソッドとして呼ぶと、`this`が変わって`Illegal invocation`になる場合があります。グローバルオブジェクトに束縛する処理と回帰テストを維持してください。

全ページを取得できない場合は、削除判定へ渡さないでください。実Chromeで画面が動いたことと、実アカウントの権限確認が済んだことを混同しません。

## 管理予定の照合を変更する場合

GoogleのイベントIDとGaroonの識別子は別です。保存済みの管理情報から照合する処理を、生成したGoogleイベントIDの一致だけへ置き換えないでください。

管理情報を持たない予定を件名と日時で推測して削除しません。変更時は[照合の要件](../requirements/chrome-extension-requirements.md#予定の照合)と、同じカレンダーを複数行で共有するテストを確認します。
