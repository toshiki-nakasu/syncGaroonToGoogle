# Chrome拡張機能の配布と更新

保守担当者が、タグから配布物を作成し、導入済みファイルを更新する責務を確認するための設計です。公開操作は[リリース手順](../procedures/chrome-extension-release.md)、利用者の操作は[更新手順](../procedures/chrome-extension-usage.md#更新する)を参照してください。

## バージョンと配布物

リリース番号の正本は`v1.2.3`形式のGitタグです。ビルド時に配布物のmanifestへ`1.2.3`を設定し、開発用manifestの版と認証設定は書き換えません。Chromeに合わせて各数値は0〜65535、全桁0は拒否します。

配布物は[packageExtension.mjs](../../script/packageExtension.mjs)で組み立てます。`chrome-extension/src`と`ui`、manifest、更新ツール、利用手順、画像を明示してコピーします。テスト、GAS、`tmp`の参考ファイルは含めません。

`docs/procedures/chrome-extension-usage.md`を配布用`README.md`へ変換します。同梱画像と同一文書内の見出しはローカル参照とし、それ以外の相対リンクは同じタグのGitHub文書へ向けます。別の正本は作りません。ZIPの日本語ファイル名はUTF-8で格納します。

`release.json`にはリポジトリ、タグ、版、ZIP名、画像名、各ファイルのSHA-256を記録します。ZIP本体のSHA-256も別ファイルへ出力します。これらは破損と配布物の不整合を検出するものであり、公開元から独立した署名ではありません。

## CIとリリース

[ワークフロー](../../.github/workflows/chrome-extension.yml)はPR、ブランチpush、`v*`タグpush、手動実行を受け付けます。タグで必要な文書の更新を取りこぼさないよう、パスフィルターは使いません。

| ジョブ | 確認または反映すること |
| --- | --- |
| `validate` | Node.js 24で構文、文書、各テスト、実Chromiumを検証し、配布ZIPを作る |
| `updater` | 生成したZIPをWindows PowerShell 5.1で展開し、更新処理を検証する |
| `release` | タグpushの場合だけ、両検証に成功したZIPをDraftへ添付して正式公開する |

タグ以外の実行では検査用の`v0.0.1`を使い、READMEの文書リンクはコミットSHAへ向けます。この成果物は正式リリースにはしません。公開ジョブが検証ジョブから成果物を受け取り、再ビルドせずに公開します。

同じタグの実行と公開処理の競合を制御し、公開済みリリースの添付物は変更しません。正式公開までの処理は同じワークフロー内で行い、トークンが起こす次のイベントには依存しません。[GitHubのイベント仕様](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)を参照してください。

## 更新の境界

[update.bat](../../script/release/update.bat)はダブルクリック用の入口で、[update.ps1](../../script/release/update.ps1)が更新処理を担当します。BATは実行前に処理ブロックを読み込むため、更新中のランチャー差し替え後に未読の行へ依存しません。PowerShellも関数を読み込んでから処理を開始します。

更新元は導入済み`release.json`のGitHubリポジトリに限定します。最新の正式リリースから固定名のZIPとチェックサムを取得します。非公開リポジトリは環境変数のトークンを利用し、配布物へ保存しません。

1. 一時フォルダーへダウンロードし、ZIPのSHA-256を照合する。
1. 展開前に絶対パス、親参照、重複項目、リンクを拒否する。
1. リポジトリとタグ、全ファイルのSHA-256、manifestの版、想定外ファイルの有無を確認する。
1. 旧`extension`を削除して新しい内容をコピーし、文書と更新ツールを置き換える。
1. `release.json`を最後に書き込み、一時ファイルを削除する。

バックアップと自動ロールバックは行いません。ネットワークと検証の失敗時は導入済みファイルを変更しません。コピー中の失敗では一部更新が残るため、同じ版でもファイルが不足または破損していれば再取得します。最新リリースより新しい版が導入済みの場合は、自動でダウングレードしません。

Chromeのプロファイルには触れず、導入先の固定パスを維持します。Chromeの再読み込みと実サービスへの接続確認は利用者が行います。これらはCIのAPI代替テストで完了したとは扱いません。
